# Change Pre-Planning

**Associated Procedure:** [[GSOP-1405.1 Change Control Overview|GSOP-1405.1]]

> [!warning]
> This document's status is **Pending Effective** — no effective date has been set yet. Verify current status in QualityDocs before relying on this.

## Purpose

Describes the process to determine whether a planned modification requires a Change Control, and in which system(s) it should be captured. Some modifications may not require initiating a change control through the electronic Quality Management System (eQMS) or the Global Service Management Tool at all.

## Scope

Applies to modifications within Lilly's authority/control to manage and execute, involving:
- GxP or HSE-regulated processes, equipment, facilities, or data
- GxP or HSE-regulated computer systems and infrastructure
- Modifications originating from Supplier Change Notifications (see GSOP-1301.1-TL.11)

## 1.0 General Overview

Pre-planning is the foundation of effective change control across GxP/HSE processes and regulated computer systems — ensuring proposed modifications are evaluated before initiation, confirming they meet change-control criteria, and routing them to the appropriate system based on nature and regulatory significance.

## 2.0 Determine if Change Control is Needed

**Responsible role:** Change Owner

Perform an initial evaluation of every proposed modification during Change Pre-Planning, by the Change Owner or a designated responsible function (e.g., Quality, HSE, Tech@Lilly), to determine whether a Change Control is required.

## 3.0 Determine Appropriate Change Control System

**Responsible role:** Change Owner

Once a modification is confirmed to need Change Control (per Figure 1), determine whether it should be managed in **eQMS** or the **Global Service Management Tool**, based on the change's nature, ownership, and execution.

> [!note]
> The source PDF includes "Figure 2: Change Control System Determination," a decision diagram that didn't extract as text — refer to the PDF/eQMS directly for the visual.

> [!warning]
> Only create a change record if at least one change action will occur in the GxP/HSE Business or Regulated Computer System domain. Avoid creating records that merely reference another change record.

Owners of change controls within each system are jointly responsible for alignment, traceability, and eliminating redundancy between related records — the linkage must be documented in *both* systems.

**Example implementation steps by system, when managing a change across dual systems:**

| eQMS | Global Service Management Tool |
|---|---|
| Technical document updates | System changes requiring a system admin |
| Impact/Risk assessments and actions for the full scale of the change (e.g., across multiple systems/enterprise applications) | Code changes |
| Changes to required information/workflows for GxP processes facilitated by a computer system | Upgrades to system software and associated documentation; periodic patches; data changes |

See Appendix A for more examples.

## Appendix A: Examples of Modifications and Associated Management

Not exhaustive — doesn't replace outcomes from Figures 1 and 2.

| Modification Type | Appropriate Management Pathway | Additional Considerations |
|---|---|---|
| Modifications affecting business process and validated state of computerized systems (e.g., updates to MES, LIMS) | Dual System Change Control (eQMS + Global Service Management Tool) per the respective procedures | Consider dual-system change control even if the Global Service Management Tool change is via a pre-approved change. |
| Modifications to validated state of internal/third-party facilities, utilities, or physical equipment (e.g., GMAR-managed assets, environmentally controlled spaces); modifications to manufactured/distributed product incl. new product introduction or deletion | eQMS Change Control per GSOP-1405.1 | — |
| Modifications to IT infrastructure impacting a validated/GxP-relevant system; data changes requiring system admin execution | Global Service Management Tool Change Control per LCS-501 | If the change is to Master Data (governing, non-transactional data or selection values) for a GxP system, consider whether an associated eQMS change control is also needed for mitigating actions (dual system). If no eQMS change is needed, document required pre-deployment business actions in the Global Service Management Tool. |
| New procedures or procedural updates that don't affect validated state | Per GSOP-1501.3 (Quality System Architecture Document Lifecycle Management) | If part of a larger-scale change control, track this process's completion as a change action/step within that CC. |
| Routine maintenance (e.g., equipment cleaning, filter change, HVAC inspection) | Per GQS215 (Maintenance) | — |
